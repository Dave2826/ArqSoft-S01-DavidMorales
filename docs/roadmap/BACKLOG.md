# Backlog

## Objetivo

Mantener un registro priorizado de todas las tareas, funcionalidades y mejoras pendientes para MotoTrack.

## Alcance

Este documento cubre el trabajo futuro del proyecto, organizado por estado y prioridad.

## Categorías

| Estado | Significado |
|---|---|
| Pendiente | Tarea identificada pero no iniciada |
| En desarrollo | Tarea asignada y en progreso |
| Bloqueado | Tarea que depende de otro cambio |
| Completado | Tarea finalizada y auditada |

## Estructura de cada entrada

```
- [Estado] Título
  Prioridad: Alta / Media / Baja
  Descripción breve del objetivo
```

## Secciones del backlog

- **Funcionalidades**: nuevas capacidades del sistema (ej: exportar reportes, notificaciones).
- **Mejoras técnicas**: refactorización, optimización, deuda técnica.
- **Documentación**: ADR pendientes, diagramas faltantes, guías.
- **Infraestructura**: CI/CD, contenedores, scripts.
- **Ideas futuras**: conceptos exploratorios sin prioridad asignada.

## Buenas prácticas

- Priorizar tareas que desbloqueen otras dependientes.
- Mantener el backlog actualizado después de cada actividad.
- No incluir tareas completadas sin moverlas primero a CHANGELOG.

## Consideraciones finales

El backlog es dinámico. Las prioridades pueden cambiar según la dirección del proyecto o requerimientos externos.
